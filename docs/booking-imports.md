# Reservation CSV import

Bookings → Import reservations uploads one CSV for one existing owned listing. Hosts map up to 64 columns to six required fields (original booking ID, guest, arrival, departure, guests, status) and optional phone/note. The downloadable template contains headers only. No provider-specific CSV column names are assumed; no real export file has been supplied or validated yet.

Dates must be YYYY-MM-DD; listing-local check-in/out settings remain authoritative. Confirmed/booked/accepted normalize to confirmed; cancelled/canceled normalize to cancelled. Pending/inquiry stays, calendar blocks, listing creation/settings, financial charges, payments and taxes are outside this importer. Files are limited to 512 KB, 200 rows and stays of 1–365 nights. Only phone last four digits are saved; full phone numbers remain transient in the browser CSV state and are not sent to the import RPC.

Every row is previewed. Invalid dates, counts, phones, listing limits, repeated original IDs, existing calendar blocks/bookings, file overlaps and probable existing bookings (same guest/listing/dates) block the batch. Cancelled stays do not occupy dates. Checkout and same-day arrival do not overlap. Correct the source CSV and upload again; this version does not edit or omit individual failed rows.

The SECURITY INVOKER `ts_import_bookings` RPC locks the owned listing, validates normalized JSON again, and inserts the entire batch in one transaction. The existing exclusion constraint handles concurrent calendar changes. Any failure rolls back every booking, receipt, task and plan from that request. MFA/owner RLS and explicit grants apply with the existing pilot exception. Immutable `ts_booking_imports` receipts keep source, original ID, original normalized snapshot and booking ID, uniquely scoped to owner/source/original ID. Original ID case is preserved. The booking's manual creation source is retained; the receipt supplies its export origin.

An identical imported snapshot is skipped even if the live booking was later edited/cancelled; replay never restores original details. A changed snapshot or different listing with that original ID requires review in the normal booking editor. Automatic amendment/cancellation reconciliation is not implemented. Stable original IDs are essential; re-exporting with different IDs cannot guarantee deduplication. Possible duplicates are flagged rather than silently linked to manual records.

Confirmed imports create the existing cleaning/inspection tasks (including historical stays), occupy the calendar and participate in TV personalization and access planning. The host explicitly confirms these effects. Imports do not provision physical door codes or send messages. `import_messages_held=true` suppresses imported message drafts, including rules added later. A separate message-delivery review/release flow must be implemented before delivery activation; ordinary reimports do not release the hold. Cancelled imports create no turnover tasks. Existing guest messages are never sent by this release.

No actual guest records are imported during deployment. Local tests cover CSV quoting/malformed files, field mapping, strict dates, phone suffixes, limits, duplicates, changed receipts, occupancy, atomic rollback including tasks, repeat imports after cancellation, message holds, receipt immutability, cross-owner isolation, MFA and anonymous denial. Production smoke checks use rolled-back synthetic records. Live browser verification is unavailable due the browser credential-session blocker.
