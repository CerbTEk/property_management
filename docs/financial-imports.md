# Booking charge CSV migration

Bookings → Import booking charges maps a CSV to imported reservations using owner, source and original booking ID within the explicitly selected listing. Reservations must already have booking-import receipts. Guest name, arrival, departure and guest count must match the current confirmed booking exactly; unsupported currency, missing bookings, changed details, cancelled stays and pre-existing charge history require review.

The header-only template supports up to 200 charge records / 512 KB. All 13 fields are required: original booking ID, guest, arrival, departure, guests, USD currency and seven itemized dollar amounts. Enter explicit zeros for absent accommodation discounts, cleaning, extra guests, other fees, tax and host channel fees. Accommodation must be the whole-stay amount before discounts; net-only export totals need explicit reconciliation before import. Amounts accept at most two decimals and $10 million per field. Discount cannot exceed accommodation; host channel fees cannot exceed the guest total. The guest total is accommodation minus discount plus fees and taxes; host channel fees are separately displayed. No current pricing estimate substitutes for historical amounts.

The preview identifies every record, shows itemized charges and sums only new valid records. Any flagged row blocks saving the entire batch. Hosts review charges against their original records and explicitly confirm. Actual Uplisting/Airbnb export formats and financial semantics have not been validated because no real export file has been supplied. No source-specific column assumptions or automatic currency conversions are made.

`ts_import_financials` uses SECURITY INVOKER, owner/MFA RLS with the existing pilot exception, explicit grants, an owned listing lock and owned booking locks. It revalidates dates, identity, whole cents and financial limits server-side and invokes the existing immutable financial save RPC with expected revision 0. It rejects any existing charge history rather than appending an automated revision. One transaction saves all first charge revisions and immutable `ts_financial_imports` receipts; any error rolls back both. Receipts retain the normalized original snapshot, source/original ID, listing, booking and saved charge IDs. Their insert guard verifies the owned original booking link and matching charge snapshot; anonymous access and receipt mutation/deletion are denied.

Identical receipt replays skip even after later manual financial revisions, guest edits or cancellation. Changed original charge snapshots require normal Booking amounts review. Replaying cannot restore cancelled bookings or replace later amounts. Moving a booking away from its original imported listing requires separate reconciliation; the importer does not transfer it automatically. Original IDs retain case and must stay stable across exports.

Imported first revisions feed existing Reports and booking balances. They describe agreed charges, not payment evidence. This release does not import payments/refunds, move funds, verify processor receipts, calculate/remit taxes, reconstruct cancelled-stay settlement or import host payouts. No real guest financial records are created during deployment.

Validation covers exact cents, itemized totals, missing amounts, currency, identity/context, deep receipt equality regardless of JSON key order, duplicate and changed receipts, replay after later revisions/cancellation, existing-charge rejection, atomic rollback, immutable receipts, ownership, MFA and anonymous denial. Live smoke checks use rolled-back synthetic records. Browser screen verification remains unavailable because the browser credential state cannot resume.
