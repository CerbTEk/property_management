# Staff task access

Hosts create seven-day invitations for an active roster entry and an email address. This does not send an email. Hosts share the public /staff/ link. Staff create or use a Treestand account with that email, verify it, enroll an authenticator and accept the invitation in their staff workspace. Email ownership is checked against auth.users; JWT email/user_metadata are never used as authorization evidence. No invitation token is needed because the verified account identity is the proof.

All staff RPCs require verified identity and aal2. The host development pilot exception only applies to owner invitation administration; it does not bypass staff MFA. Staff can belong to multiple host rosters, but only tasks currently assigned to their accepted active entries are returned. Inactive roster entries, revoked memberships and reassigned tasks disappear on the next request. Reactivating an entry restores access through an accepted membership unless its invitation was revoked. Explicitly revoked memberships require a new invitation and acceptance.

RPC responses expose work details, property name/timezone, host task instructions, checklist, status and staff work notes. They exclude reservation IDs, guest names, phone endings, prices, lock IDs/codes, provider credentials and other host records. Staff have no direct access to the private membership/read/preference/activity tables. Public API functions are invoker wrappers around private, explicitly authorized implementations. Schema usage permits those function calls without any table grants. Existing host table policies are unchanged. Staff may start open work, check items, save a separate worker_note and complete all checklist items. They cannot dismiss/reopen historical work, edit task identity/assignment, change checklist labels or update cancelled-booking tasks. Updates require the expected timestamp and recheck membership after locking. Membership/person locks serialize revocation/deactivation against updates. Staff actions are recorded in a private activity journal.

In-app notifications are revision-based: assignments and host edits appear as new/changed, with persistent reviewed receipts and due/overdue filters using the property timezone. Successful staff actions mark that revision reviewed. The screen refreshes every 30 seconds while open. Notification preferences support in-app reminders and requesting future email delivery. The staff email endpoint and signed receipt handler are built, but delivery remains setup_required until a dedicated verified sender and server credentials are configured. There is no automatic digest scheduler or SMS transport in this release. Resend's current verified domains belong to other products; activate a dedicated verified Treestand/CerbTek sender before enabling outbound delivery. Do not flush old prepared messages or imply queued staff notices have been emailed.

No real staff invitations, account creations or email sends are performed by deployment. Validate the first staff account's confirmation, MFA, acceptance, checklist completion and revocation before onboarding a real cleaning team. The staff signup confirmation redirect uses /staff/; ensure that route is permitted by the project's authentication redirect allowlist, or use the shared staff link after email verification.
