# Listing CSV migration

Properties → Import listings from a CSV supports up to 50 listings per 512 KB file. A header-only template is included. Hosts map original listing ID, name, timezone, USD currency, weekday rate, Friday/Saturday rate, channel markup, guest capacity, minimum nights and 24-hour check-in/out times. Every field is required: missing values are never inferred. No actual Uplisting/Airbnb export has been supplied or validated, so source-specific column names are not assumed.

The preview shows all settings. Hosts choose Create new listing or an owned existing listing for each row. Linking requires all imported values to exactly match existing settings, including minute-precision times; it never overwrites a listing. Existing name collisions and repeated IDs require review. Correct mismatched settings through the normal listing editor or the source CSV before linking. Timezone aliases are not silently canonicalized. Original IDs retain their case. Existing links to another original ID from the same source cannot be reassigned.

`ts_import_properties` uses SECURITY INVOKER, owner/MFA authorization with the existing pilot exception, explicit grants and an owner-scoped transaction advisory lock. It validates all fields server-side, locks an owned existing listing before linking, and saves an entire batch transactionally. Any failure rolls back newly created properties and receipts. Immutable `ts_property_imports` receipts retain the original normalized snapshot, source, original ID and Treestand listing ID. Identical repeat imports skip even after later listing edits; changed snapshots require review rather than restoring old settings. Receipts are owner-only, inaccessible anonymously and cannot be changed or deleted.

Imported and linked listings become selectable in Bookings → Import reservations. That selector shows the original listing ID from the chosen source when available. Hosts still choose a listing explicitly; this release does not automatically split a multi-listing booking file or apply provider updates.

Only basic listing configuration migrates. House rules, photos, welcome content, dated rates, cleaning/extra-guest fees, discounts, taxes, locks, credentials and channel connections require separate setup. No booking financials or payments are created, no guest messages are sent, and channel rates are not published. Creating a property follows the existing access-plan invalidation trigger; it does not provision physical codes. Real property records are not imported during deployment.

Tests cover precise money/markup, currency/timezone/time validation, limits, missing/duplicate mappings, name/ID conflicts, exact-match linking, existing-listing preservation, immutable receipt replay, all-or-nothing database rollback, cross-owner isolation, MFA and anonymous denial. Live smoke tests roll back synthetic records. Browser screen verification remains unavailable because the browser credential state cannot resume.
